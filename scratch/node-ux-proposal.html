02 · wiring ops：chat 布线的地基

手动布线与 chat 布线不互斥——同一套 mutation 层，UI 只不开手动

op语义场景演示
add_node画布落一个节点（孤岛合法——图是森林，不必连通）B：孤岛提示词节点出生
connect连一条 typed 边（载荷类型决定颜色与落点）B：提示词 → 图生成，边随节点一起长
edit_prompt改某节点的 prompt（直改或 chat 指认，同一 op）C：Post prompt 直改
run(_subgraph)填充一个节点或它的下游子图（执行事件，hold→capture→release）A：跑全图；C：重跑局部
delete_node删节点（下游产物语义简报里定）—
端口法则进 = 消费区域最左下角（prompt 区）；出 = 生产区域最右上角；同侧多端口顺角堆叠（ElevenLabs 实测解剖）全部场景
03 · 积分三面

草稿态逐节点估价 · 确认才扣 · 语义台账

草稿态估价图先铺开零消耗，每个未运行节点带自己的估价（「运行后生成 · 约 N 积分」）；全图总价在 chat 确认 pill
节点锚定确认边际价 = 重跑子图 fold（没动的不收钱）；波及面 chips；余额软对照；422 仍是事实源
语义台账hold/release 永不上 UI；按 run 事件一行一事（首次全图 −12 / Post 修订 −3 / 赠送 +500）
免费层改字免费即时；chat / 素材处理不上账（鸡毛蒜皮不上明面）
04 · 不变的法（2026-09-07 拍板）
  • 图即产品对象：常驻、可突变、agent 搭建、用户看见；运行 = 填充节点；修订 = 原地突变。
  • chat 唯一操作面 + 节点直改并存：prompt 直改走同一 wiring op（edit_node_prompt）+ 价格确认——直改已拍板，不是第二通道。
  • 双图坍缩为一图：执行图即展示图；steps 住节点体内（组合非投影）；ADR-036 投影模型与五补丁同批火化。
  • 确认才花钱：hold→capture→release、失败不扣费、负余额语义全部不变，重锚到 执行事件+节点。
  • spec/任务书词汇退役：用户世界只有「这张图」和 chat；任务书 = 文档节点（②型）。
  • 首站 = 迁移现有管线（修订环随之根治），生成类配方第二批；内核批排期提到最前。
