Graph 空间模型合同 v2

Entity / Birth / Hierarchy / Identity / Layout 五条合同，每条带代码取证（2026-09-25）。核心翻案：Graph ≠ Plan 的可视化结果；Graph = Agent 与用户共同工作的、持续存在的内容世界——图只在新的持久 Product Entity 出现时生长（Agent 的思考、读取、改写永不产节点），节点只长不消。四个事实从此分离：graph entity exists（上传即始）、canvas visible（首个非 source 节点出生 = Agent 开始建立工作世界）、plan ready（canonical lifecycle projection，不动）、confirmation（授权拍，不是 draft 出生拍——代码早已如此）。下半 = T0–T6 连续生长时间轴，每帧画全量。

C1

Entity 与 Birth — 什么配成为节点，画布何时出生

Product Entity 准入律生长原则

Graph 新增节点 ⟺ 产品世界里出现了一个新的持久 Product Entity。合法出生只有五类：

  • Source：用户素材落库（stamp_asset_node graph_fill.py:235，上传即落图，born done）
  • Evidence：素材的持久理解产物（转写稿 stamp_transcript_node graph_fill.py:320——上传即出生 queued，ASR 落地翻 done；调研简报同族）
  • Judgment：探索产物（候选集——一组证据的合集对象，R1 合集律）
  • Plan：计划结构与 draft 作品（stamp_draft_graph，PLAN_READY 时刻出生，service.py:1188/1675）
  • Work：run 填充的作品实体（draft 原地转 running → ready，不新增节点）

永不产节点：Agent 的思考、搜索、读取、改写措辞、相机移动、引用指认。否则 Graph 退化为操作日志。

C2

Evidence 锚链 — 金句候选的语义定义

先定义语义，再谈 UI

Candidate = 与原始媒体时间范围绑定的证据对象语义定义

现行代码已满足（exploration_store.py:99 CandidateMember）：

  • source asset — 候选集合挂在 asset_id 上
  • source range — {start, end} 秒数区间，这是候选真正的根
  • excerpt — 区间内逐字验证过的原话（门拒绝"那里没说过的话"：words_in_range / get_segment 对 words 核验）；excerpt 是展示文字，从不进渲染
  • speaker — best-effort（audio 素材无 speaker_map）

锚链全图：Asset.meta["words"]（词级 {word, start, end}，时间唯一权威，ASR 出生即定格）→ cue 行分组（[start-end] 锚）→ candidate {start, end, excerpt} → select 指针 → run span → clip-spec start_seconds/end_seconds（locate_span 把粗时间戳吸附到词边界）。

五问五答代码取证

问答（代码事实）
candidate 必须是连续时间范围吗？是。{start, end} 单一闭区间，无多段并集。跨段拼接若未来需要，是新实体类型（复合候选），不是放宽现有字段
能跨 transcript segments 吗？cue 行只是展示分组（标点/停顿/词数触发断行），candidate 区间自由跨越 cue 边界——范围对 words 核验，不对 cue 核验
时间码唯一权威是谁？Asset.meta["words"]（ASR 词级时间戳）。excerpt、cue 锚、clip-spec 秒数全部由它派生或向它吸附（locate_span）
用户改 quote/transcript 文字后，range 保持吗？保持，零漂移——没有任何代码从文字反算 range；range 是秒数，活在 words 轴上。⚠️ 唯一隐患：excerpt 逐字核验读的是原始 words，用户改过文字后，未来新候选的 excerpt 以 ASR 原话为准，可能与用户编辑版不一致（合同条款：编辑 = 表达层，核验层 = 原始语音事实）
生成 clip 消费 excerpt 还是 source range？range。cut.py 消费 span 秒数 → clip-spec start_seconds/end_seconds；excerpt 只是候选的展示面与核验副产品

Transcript 编辑 = 表达层编辑新条款

  • 用户可直接改画布上的转写/金句文字，也可叫 Agent 改——改的是表达层（Asset.transcript + 节点 spec["text"] 镜像），永不触碰 meta["words"] 与任何 range
  • 时间码、候选区间、切片入出点不因文字编辑移动一秒
  • 编辑痕迹可视化（edited 标记），核验层始终读原始语音事实——「你改的是说法，不是证据」
  • 现状缺口：transcript 文字今天没有编辑写口（无 API 无 UI）——这是新能力，不是已有行为的澄清
C3

Identity — 选择是决策状态，不是节点

Selection 降级为状态删除「已选」卡

代码事实：SelectSpec（exploration_store.py）已经是纯指针——{candidate_set_id, member_index, verdict, reason}，从不拷贝源。「用户做了选择」的产品语义 = 候选集内的成员状态翻转，不配拥有独立节点：

  • 读面：pick 态收进候选集卡行内（左缘蓝条 + ✓ 标记），「已选 · 5」卡删除
  • 数据面：零迁移——SelectSpec 指针继续作为 Plan 的结构载体（plan 的 range/source 由它送达），只是不再渲染成卡
  • 「第二段换成讲 roadmap 的那段」= revise_selects 重指同一集合的另一成员（已有工具），画布上的表现 = 行内 pick 态搬家

sibling ≠ version 旧律保留：版本住作品卡内（pager），sibling 扇出归组。扇出规模移交 C4 的容量律统一表达。

C4

Hierarchy 与 Layout — 秩呈现 + 组内局部布局

病根诊断取证

x = depth × _PITCH（graph_store.py:382）不是病根——它是拓扑生成代的忠实渲染（子节点恒在全部父节点右侧 ≥64px，列缘永不参差）。同 depth sibling 今天已经垂直堆叠（y = column tail + _GAP_CROSS，统一摆位律注释原文 "siblings stack in place"）。「数据库感」的两个真实来源：① 秩盲——六类语义身份同一视觉寄存器；② 无界列——列高只长不收，6 条 9:16 竖片 ≈ 4200px 一柱擎天，相机 fit 时全缩成邮票。

组内局部布局律新条款

  • 同一 sibling group（同 depth + 同语义父）默认从上往下排——现行法律，不动
  • 达到局部容量 C（视觉参数，非产品规则；初值按帧高估算，竖片列 C≈4）后，溢出成员向组内第二列扩：x 在本 depth 带内右移一档（+ frame_w + gap），depth 不变、拓扑不变、不升成全局新列
  • 后续 depth 带的列 x 按前面带的实际占用右缘让位（depth-pitch 从「固定 464」改为「前带最大右缘 + gap」——带内宽度可变，带间纪律不变）
  • 保序律不变：已落帧永不移动；容量溢出只影响出生时刻的摆位
秩节点视觉寄存器
Source 源素材卡最实：媒体撑满；秩标 = 无
Evidence 证据转写稿 / 调研简报文本卡窄一档；可直接编辑（C2 表达层条款）
Judgment 判断候选集集合形态一卡（R1 合集律）；行 = timecode + excerpt + pick 态
Plan 计划draft 作品（虚线 + 估价）PLAN_READY 出生；确认拍在 dock pill，不占卡
Work 作品短片 / 帖子 / 文章 / 轮播图 / 金句卡最高：媒体撑满 + 序数角标 + 组内扇出
Revision 版本作品修订版不占列——住作品卡内 pager；「刚更新」徽衰减
C5

交互语气 — Reference 是系统语义，不是台词

  • 用户指认对象的手段 = @mention chip / 画布直点 / 自然语言（"第二段开头短一点"——系统内部解出目标即可）
  • Agent 回复永不机械报号：「好，把开头那句铺垫去掉了」✓；「好的，我将修改第 2 条」✗。序号为系统语义存在（锚定/聚焦/hover 高亮），不为台词存在
  • Agent 的 canvas 引导句只在需要指路时自然点名（「排在画布上了」），不逐条播报
  • Confirmation = 授权拍：图在 PLAN_READY 已长满 draft，确认只翻转授权状态，不出生任何节点
