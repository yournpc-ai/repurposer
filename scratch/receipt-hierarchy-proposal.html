设计决策点（待拍板）
  • A vs B：导轨是不是合法笔画。我方观点：导轨 = 树形层级导引（Claude Code / 文件树同族），不是分区隔线，不违「分隔来自间距与 token 阶」。
  • 删除线：E1（全划）否——收据不是 todo，产出不该被勾销；E2（只划 no-op）可——「被划掉的一步」语义恰合，且与降灰可叠加（划线表"未做"、降灰表"耳语"，一个表语义一个表声量）。
  • 组件结论：截图 = Vercel AI Elements 的 Queue（Radix 风味）。核心 shadcn/ui（我们的 base-ui 版）无此类组件；Queue 只有 completed/pending 二态，无 running shimmer / failed / waiting / 读秒 / SSE——我们是 base-ui 栈且 RunTaskList 已自带全部 run 态机器，采纳 = 在外来壳里重建已有状态机。取视觉参照，不取代码。
  • ✓ 单发：步骤行去 ✓ 后，「全成」由头行圆章一次说完；失败行第一次获得对比度。
  • 声级判定：no-op 判定的服务端信号是现成的（summary 含 "skipped"/"drafting directly" 或 step 无 output_refs）——建议按 无产出 + skipped 语义 降灰/划线，不认字符串。
  • 守 09-05 退役裁定：不把 4 行 prelude 折叠成 "Preparation · 4 steps" 假中间层——只降灰/划线，不重组。
