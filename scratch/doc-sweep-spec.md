# 文档去历史化大修复 — 统一施工规格（2026-09-28）

> 你被分配了一组文件。本规格是唯一的施工法律。施工目标：文档只承载**现行法**（现在时直陈），历史在 git，不留痕。文档治理三铁律：不保留历史 / 只摆事实 / 论证归 STRATEGY.md。

## 删/改模式（逐条执行）

1. **日期+过程叙事**：「（2026-09-23 用户拍板）」「2026-09-27 翻案」「同日三轮修订」「2026-08-30 实测坑」「2026-09-06 A/B-tried and closed same-day」→ 删除日期与过程注，法则本体改写为现在时直陈。
2. **翻案/收窄/叠加链**：「X（翻案：旧裁定 Y 废止）」「A 曾如何，2026-XX 改 B，后再收窄为 C」→ 只保留最终现行法 C 的直陈；若 C 在上下文已被陈述，整条删除。
3. **RETIRED / 退役 / 废止 / 火化条款**：`~~删除线~~` 条目、「已退役」「已火化」物件 → 整条删除。例外：禁令类若仍是现行法，保留禁令并改写为现在时（如「stadium 只属于真单行盒」）。
4. **「曾 / 原先 / 旧版 / 首版 / 早些时候 / 此前」对比叙事** → 删旧留今，今态改写为直陈（不留「现在改为」这类过渡词）。
5. **事故/事件名叙事**：「RecipeInspectOverlay lost it once」「09-08 ask 散文瞬移事故」「caption 配方卡两连击全灭的判词」→ 删事件名与日期；若事件承载教训，教训凝练为法则一句。
6. **复发史/试错史**：「试过 X（被否）、试过 Y（被否）——终裁 Z」→ 只留 Z 及 Z 的理由（一句话），试错过程删。
7. **Status 行**：保留 `> Status:` 行与状态词，删掉里面的过程叙事（保留一个最后更新日期戳或无日期均可）。

## 保留（勿动）

- ADR 编号纯引用（ADR-046）、章节指针（§8.6、STRATEGY §5）——引用本身不是历史
- 参照锚名称（Lovart / FLORA / ChatGPT / MiniMax / Claude Code parity）——设计依据，不是时间叙事；但它周围的过程故事（何时对照、几轮实拍）要删
- 排期语义的时间词（W7、第九周、周期表日期）
- 操作性括号：例外清单、取值表、像素值、比例、字段名
- 代码标识符、文件路径、表名、列名
- 禁令本体（「永禁」「禁止」「不得」）——只删它的来历故事

## 铁律

- **不改变任何现行法则的语义**。删到读不通 / 有歧义就停手，记入存疑清单。
- 不重排章节、不改标题层级、不删表格行（除非整行是被废止物）。
- 不碰 `docs/archive/`、`docs/research/`、`docs/tasks/`。
- 删完日期注后句子常需要重连——每处改完自查：无悬空破折号、无「同日」「同批」「此前」等失去锚点的词。
- 用 Edit 逐处修改；每个文件改完后，重读你改过的段落确认现在时通顺。
- **不 commit**。

## 自检与报告

每个文件施工前后各跑一次计数：

```bash
grep -cE "2026-0[789]|翻案|退役|RETIRED|废止|曾裁|旧律|旧版|原先|拍板|收窄|红圈|早些时候|首版|第一版" <file>
```

最终报告格式（每文件一节）：
- 标记数 before → after、字数变化（`wc -c`）
- 3~6 条改写要点（哪类叙事被压成了什么法则）
- 存疑留旗清单（不敢动的点 + 原因；没有就写「无」）

注意：标记数不必清零——ADR 纯引用、排期日期、Status 行日期是合法残留。目标是**叙事清零**，不是数字清零。
