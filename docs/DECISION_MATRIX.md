# 横向决策矩阵 — 功能点 × 竞品 × 我们的决策

> **状态**: 当前决策矩阵（2026-10-25）。竞品单元格是注明日期的研究快照；“我们的现状”必须与本版链接的现行合同一致。实施批次与优先级以 `PROGRESS.md` §0 为唯一事实源，不能由本表 P0/P1/P2 推断当前正在施工。
> **用法**: 每行一个功能点；决策三档——**采纳**（照搬即可）/ **改造**（结合定位重做）/ **放弃**（附理由，防反复纠结）；现状与 ADR/PRD 对齐
> **竞品列缩写**: O=Opus.pro · D=Descript · S=Submagic · R=Repurchase.io · V=Revid.ai · C=Crayo · T=ChatCut；✓=有 · ~=部分 · ✗=无
> **事实依据**: 各单元格出处见 `COMPETITIVE_ANALYSIS.md` 与 `research/<竞品>.md` 卡片；标 ⚠️ 处为未验证

## 使用约束

- **采纳 / 改造 / 放弃**是产品决策，不是实施状态；“现状”列与链接合同才说明代码和验收边界。
- 竞品单元格保留研究时点事实，引用新证据时就地更新对应单元格，不追加逐轮对照报告。
- 本表不生成排期，也不以“P0 已完成”推断发布就绪。当前优先级、外部前置、质量欠账与上线阻塞统一归 `PROGRESS.md`。
- 放弃项只约束所写范围；如限定能力已经由另一现行合同实现（例如 `reframe_clip`），必须写清边界，不能用笼统标签否认现实或偷偷扩 scope。
