## 认领、强杀与恢复授权

Worker 使用 PostgreSQL 时钟、认领 token 和租约。图片、旁白、音乐分别限额。队列测试用 9 个测试账户，单类最多 32 个待执行或执行中的 Job，单账户最多 4 个。两个消费者竞争时两个账户可各运行一个同类 Job，另一个种类可独立领取。过期 token 被拒绝，第三次领取后再过期即结束。

四个供应商边界使用真实操作系统 SIGKILL，供应商调用用已记录的音频替代。提交前恢复后执行一次。提交后无确认保留预占，停止重发。固定原音后强杀只恢复后续处理。结算后重放保留一次捕获。另一次并发测试在旁白提交处注入超时，音乐仍成功固定。应用账本与供应商最终账单分别核对。[强杀与双恢复调用](media-faults.json) · [部分失败](parallel-partial.json)

第五处强杀发生在 Agent 续行入口。初次恢复为仅录音的请求多预占了 6 积分，测试 Stop 在领取前全额释放。修复后使用同一 opening 的原生处理函数重放原录音，再在模型边界注入新图片提案。图片只出报价，拒绝后由真实模型续行。首次复测模型尝试了无法完成的创作。第二次复测中模型插入原录音并要求导出，超过了原录音请求的范围。此时 Stop 取消导出报价，导出 Job 为零，版本、原音和单次扣费均保留。该行为证明新操作授权的资金边界。模型遵循独立素材请求的质量仍开放。[首次复测](recovery-consent-first.json) · [拒绝与 Stop](recovery-consent.json)
