## 独立的编辑和观察验证

- **模糊移动**。以用户给定的「往后移动一点」原句复验。模型选择后移 1.5 秒，右半段最终 [9.5, 12.5)，第三段仍从 13 秒开始。操作、源时间和黑场长度可从 `natural-time` 的不可变版本核验。[原始播放](iteration-2/media/natural-time-e8c0f7d98e.mp4)
- **先看、再改、再看**。`exit-compare` 在同一轮先播放 v6 的第二幕，将人物从 0.70 放大到 0.85，再播放 v7 的同一窗口。此前 `exit-size` 和 `exit-xy` 已分别缩放、平移。对同一素材的 16.5 秒帧独立复渲，人物画面水平像素范围依次为 64–254、93–226、75–208。后两次边缘都精确左移 18 像素。字幕数据逐字段相等。编码后的边缘像素允许压缩差异。[同帧对照](iteration-2/visual-comparison.jpg) · [像素测量和编码轨道](iteration-2/pixel-facts.json)
- **空档**。`exit-gap` 单独播放 [6.5, 8)，真实输出全黑，读操作没有追加版本。预览也能包含末尾空档和不超过 12 秒的整部短作品。触及半个转场时，服务端返回包含完整转场的时间要求，避免呈现丢失过渡的画面。[纯空档播放](iteration-2/media/exit-gap-85947ffaac.mp4)
- **硬刷新**。同一条 v6 消息的两张卡分别在 Chrome 点击 Play、忽略缓存重载、再次点击。两次均恢复两个播放器，访谈素材在重载后达到 readyState 4 并实际推进至约 1.9 秒，首卡在测试时刻位于黑场。两次独立浏览器探针均无 HTTP 错误或未捕获异常。[两个窗口的浏览器证据](iteration-2/two-card-refresh.json)
- **视听边界**。模型正确读出用户未提供的英文标题和字幕，辨认出白外套、吸音背景、黄黑麦克风及真实黑场。主样本的附带说明把人物左移后的左右黑边宽度说反。像素与变换均证明左边变窄。较早样本还有人物朝向、对黑场成因和标题转场的表述偏差。模型收到的 MP4 含 H.264 和 AAC，provider 能力声明 `audio_available_to_model=false`。本次验收仅证明视觉观察。

## 执行与恢复

| 场景 | 复核结果 |
|---|---|
| 同一原生调用重放 | 重启后重放同一裁剪 ID 返回原 v2 和 replayed。更改 end 后拒绝，版本总数保持 2 |
| 并发与旧基线 | 两个独立 PostgreSQL 会话同时基于 v1 移动同一 Clip。一次提交，另一次 StaleBase。同参重放命中已保存版本，异参重放拒绝 |
| Stop 先赢 | 真实 SSE 的 turn.started 后立即发 Stop。状态 retracted，版本未增长 |
| 提交先赢 | 真实 SSE 缩放完成后发 Stop。状态 cancelled，保留已经提交的版本与「已保存缩放」消息 |
| 提交后强杀 | 真实模型发起裁剪。在隔离 API 的 edit_clip 返回后、ToolLoop 获得结果前发送 SIGKILL，服务退出码 137，SSE 中断。数据库已有 v2，活动仍 active，ConversationContext 没有该调用回执 |
| 重启与刷新竞争 | 用原数据库重启正常 API，三个并发历史 GET 均返回 200。只有一个中断回执，原活动变为 completed，开场行标为 failed，版本链未增长 |
| 活跃回合的刷新 | 另一个会话持有该回合的事务级 advisory lock 时，刷新保持 in_flight。连接退出后才进行恢复 |

[强杀前后、原生 ID、实际消息和重放结果](iteration-2/crash-recovery.json) · [并发写入与 StaleBase](iteration-2/concurrent-edit.json) · [两个 Stop 窗口](iteration-2/live-stop.json)

故障点只装在一次性验收 API 进程中。包装原有 `editor.edit_clip`，先 await 真实执行体，将返回版本和工具 ID 写入证据，再调用 `os.kill(os.getpid(), signal.SIGKILL)`。重启时去掉包装。生产路径把原生调用身份、参数指纹和对应 Activity 行与不可变版本原子提交。恢复通过已有历史读取或下一次 Chat 提交触发，按真实 request_id、项目和所有者查询。各回合用原开场消息锁与 Stop 排序。区分「已保存」和「本轮中断」使刷新后的状态与版本一致。

## 实际改动和删除

- `chat.editor` 增加 `inspect_clip`、`trim_clip`、`move_clip`、`translate` 和 `scale`，沿用已有 inspect、split、preview。编辑工具对已有作品全量可见。两个 Chat 入口复用同一 ToolLoop、执行函数、事务与渲染器。
- 删除 `editing.edits.TrimClip`、内部 Op union 对应项和 `_apply_one` 的裁剪转发分支。原独立的 split 写入函数已并入 `edit_clip`。保留 `SplitClip`、`TemporalEdit` 和 `UpdateClip` 的算法与原子校验。上线前已有的同参分割请求仍能重建其原请求摘要。
- 裁剪以 Clip 自身秒数指定保留窗口，固定媒体按 1 倍速裁源，保留时间线空档。移动指定作品绝对起点，同步移动关联媒体，保持源窗。跨幕、同轨冲突、断开转场，以及破坏关联或派生字幕关系的候选由现有校验拒绝。
- 平移和缩放只改变选定可视对象的静态 Transform。平移使用相对布局框的画布像素，缩放使用相对原布局的绝对倍率，保留既有变换原点。无可编辑变换、属性由关键帧控制或请求没有实际变化时均明确拒绝。
- 已保存作品的观察与当前版本绑定。每次模型调用读取当前工程摘要。时序回执记录修改前后的实际区间，已保存动作保留在本轮。并发写入改变 HEAD 时，旧 Clip 位置和预览退出默认上下文。Chat 投影用自然时间描述替换已知的技术 ID，正文在工具结果确认后持久化。观察过的不同版本或窗口使用现有 storyboard block 分别回放。
- 继续使用 owner/project 校验、唯一版本写口、CAS、源快照、旧后台执行和账本机制。本轮未调用付费素材生成或交付，未验证新的供应商扣费或音频感知。首稿和媒体生成仍在原有路径。

## 开发期失败与验证边界

| 分类 | 实际失败和结果 |
|---|---|
| 模型工具选择 | 模型偶尔同轮提交两个调用。本轮保留现有拒绝与顺序执行规则，拒绝批次没有落库 |
| Tool 参数 | 初期猜错右半段 ID、越界预览。返回真实右半段引用、作品时长和可用时间边界。早期「已是该变换」也被明确拒绝 |
| Context 事实 | 初期折叠当前版本的有效观察太早，造成重复缩放和达到上限。改为版本绑定，保留本轮已做和已看的事实。最终比较案例只放大一次 |
| 编辑执行 | 原预览编译用最后一个 Clip 结束点决定长度，尾部空档会缩短。改用已验证的请求范围作为局部渲染时长 |
| Chat 呈现 | 早期出现短版本 ID、未选中既有计划时的提问异常、同轮仅保留最后一个播放窗和不准确的画面描述。前三项已修复，视觉方向等自由文本仍可能出错 |
| Recovery | 旧路径在版本与回执之间有持久化空窗。受控强杀、并发刷新、重放和真实 Stop 已验证。仍需刷新历史或再次提交才能显示补记消息 |

API core 全量 **535 通过**，4 条已有警告。Web Vitest **47 个文件、432 项通过**，TypeScript 检查通过。新增定向回归覆盖五次写入各自的同参/异参重放、关联音画裁剪与移动、字幕和动画保持、转场、碰撞、越界、空档时长及活跃回合防误恢复。旧 §9A / §9B 在原提交链内。这一轮未启动官网四轮验收和 Iteration 3。
