### 0.3 工作约定

- 不擅自付费生成、部署、修改生产数据或重跑事故项目；真实 LLM/TTS/付费渲染先列范围与预算并获授权。

- 付费验证入口显式设置 `MINIMAX_WARMUP_ENABLED=false`；所有真实模型 HTTP（含 warmup）计入预算。
- 每轮只承接一个明确范围；先核对 current code、迁移、现有未提交改动和并行归属，旧文件/行号只作导航。
- 规则变化更新其唯一事实源；普通实现修复、字段接线和测试结果不新增 ADR。真正改变架构边界、产品语义或关键取舍才新增独立决策。

## 1. 当前验收与上线条件

### 1.1 下一验收窗口

详细欠账及每项证据边界由 [progress 当前未验证项](film-storyboard-orchestration-progress.md)维护。下一验收窗口按下列组组织，完成一项就在 progress 替换状态，不在本文追加验收日记：

| 组 | 必须回答的问题 | 主要证据 |
|---|---|---|
| 授权与恢复 | auto 档是否保持“免批准拍但不创造制作意图”；过期 `base_ref`、断流恢复是否安全、诚实 | 真实 Chat/SSE、版本与 run 记录 |
| 展示 | live now line / WorkSegment / 修订呈现是否与实际工具和世界状态一致；真实断网、停止、Start recovery、刷新回放是否无假状态 | 浏览器逐拍观察；不只靠回放或纯测试 |
| 双源与文字 | 网页源链在本迭代后是否仍通；纯文字零媒体、用户点名更快节奏、逐句子句与同回合纠正是否按真实需求工作；8 幕目标、末幕两行严格纯滑动、旧分组清除与“呈现版 = 实际 run 版”是否在隔离项目成立 | 真实 LLM 旅程 + 成片/帧检查；连续不同非法参数的第 3 次拒绝终态；不得复放事故项目 |
| 回答入口 | 从问题选项进入首次设计的原始旅程是否成功，回答与 brief 回填是否耐久，首次 begin 拒绝是否终止重试而非误报能力缺失 | 原入口人工复测 + 受影响测试/诊断 |
| 回归闸 | 累计 prompt 面是否通过 prompt_gate；受影响剧本矩阵是否通过；begin 结构化改动后的同步测试是否已跑 | 仪式链实际输出；授权与配额边界另记 |
| 视听事实 | 实际音轨是否独立听过；文字观感词汇是否在动态成片中符合要求；组合片 Tasks 名称是否准确 | 人工试听/看片与真实 Chat 观察 |
| 长片边界 | 139s 案例是调整全链上限并验收，还是明确不承诺；不得静默截到 120s | 有结论后更新当前范围与 PROGRESS |

#### A. 授权、版本与证据包

1. **首稿与 Start**：首条“直接做”也只能先完整呈现作品首版；无关问答不得解除 review hold。旧 Start 在新版本出生后失效，新 Start 只绑定新版本。分镜超时或模型失败必须收束活动与 draft 等待，不出现永久 busy。Film 与非 Film 各验证一条 typed Start，确认共用通道没有回归。
2. **普通修订**：只保存新版本，不创建 run、不先出制作 dock；回复说明尚未重新制作，并展示系统变化摘要、完整当前保存表、累计设置与具体未解决项。用户表不得出现内部 `scene_id` / `base_ref` / digest。
3. **后续明确制作**：不得重新设计；进入既有提案、报价与执行，旧 Output 保留。未释放 drift/shortfall、review hold、守卫线与费用确认继续生效。
4. **“修改并制作”同回合委托**：完整呈现后进入既有提案，不机械增加第二轮批准；是否立即开工仍由设置与确认债决定。review-only 则完整呈现后停止，无开工问题、dock 或 run。
5. **漂移与范围**：动画-only 额外改字、删标点请求额外删句、已有 drift 后再改无关字段，都必须保留差异与保护；结构化 patch 或无关修改不能销账。
6. **执行身份**：`run.context` 的 presented version / digest / params 必须等于刚呈现版本；pending 正常消费，后续默认编辑基准与实际 Output 一致；不得经 `edit_graph` 生出无版本封套的 Film run。
7. **形状三态**：`target_seconds` / `scene_count` / `group_chars` 分别验证省略继承、给值覆盖、显式 null 清除；清除后 canonical params 与 launch slot 均不得再携带旧键。
8. **真实证据包**：完整对话、设计授权消息 id、版本与参数、content/execution digest、呈现消息 id、生产授权来源、dock quote、run id、`confirmed_scope`、worker `prepared_storyboard_used`、render-spec provenance 和可播放成片链接。缺少身份链时不得把“能播”当作版本闭环通过。

#### B. 严格动画与有界失败

1. **8 幕保留范围**：在隔离项目只改末幕为两行顺序纯滑动，前 7 幕必须不变；先核对 change_set，再核对实际 run 版本。
2. **逐行纯滑动帧验收**：`enter_start=0.3`、`enter_interval=0.5`、`enter_duration=0.4` 时，30fps 下第一行 f9 开始、f21 完全进入，第二行 f24 开始、f36 完全进入；f24 前第二行不可见，入场无 opacity 渐变、blur 或 rise 残留。必须检查真实动态帧，tsc 不算视觉验收。
3. **重复拒绝终态**：同签名第 2 次设计拒绝即停；不同签名最迟在同回合第 3 次停止。最终必须有诚实 assistant 终态，不留 busy、不转整稿导演、不创建 run；已保存版本与旧成片保持，未保存时不得谎称已有新版。

#### C. Chat / Run 工作段与恢复

1. 普通工具回合应在同一工作段原位经历 Thinking → 当前活动 → Worked → 正文；Worked 前无 chevron，且不存在第二条 Thinking。多工具回合按实际可见散文分段，首个正文字符释放时冻结耗时。
2. cancelled 尝试不得显示为失败或成功；真实 failed 保留安静告警。纯 chat 不出现空工具框，刷新后无残留 shimmer，历史只显示可观察活动跨度。
3. 首稿完整表格与独立开工句必须先排干再挂 run；旧方案普通 Start 不重复 echo，零正文 Start 不产生空泡。Path A checkpoint rekey 不得重复收段或改变 `birthKey` 身份。
4. run 同一行经历制作中 → REVIEWING → 匹配当前 run 的 delivery 首字后 Worked；chip 由真实可交付 output 独立出现，不等回复。分别核对成功、部分失败、全败、60s 无回复、迟到回复与刷新历史。
5. 真实断网、用户停止与 Start recovery 必须端到端复测。恢复只读且不自动重试制作：原问题行的 `workflow_run_id` 优先于新 pending dock；pending-without-run、settled-without-run、读取失败/超时与未知状态分别诚实呈现，恢复查询必须有界。

#### D. 网页 / MG / 采集旅程

1. **主旅程**：URL 或 `@web_page` → 真实读取与分镜 → 首稿完整呈现并等待 → 用户看后批准/Start → `web_page → generator → video` 血缘 → 可播可下载成片；报价与实扣对账。不得沿用“首稿 auto 直接开工”的旧预期。
2. **能力问答与移动交付**：用户语言的能力回答包含真实 MG 能力、零工具名且与 registry/配方一致；移动端有承接、收据与可播放锚卡，桌面行为不回退。占位 Home 样片不是本项证据。
3. **B1 采集**：真实 DOM/JS 页面产出生效 section shots，fold 保留；Chrome 缺席时 `screenshot=None` 且链可降级继续。核对系统 Chrome 版本兼容、长会话 PolicyProxy 稳定性以及 capture/processor 超时预算。
4. **B2 元素相机**：focus 以 element id 为主，服务端推导坐标 ∈ [0,1] 且落在元素盒内；不得接受模型盲猜坐标。
5. **B3 节拍**：幕边界只在容差内 snap 到 beat grid，snap 后 narration 不越界截断。
6. **B4 子页**：首页输入产生 1 个主资产与不超过 3 个同 host 子页资产；login/blog/legal 等 BAD_LINK 被过滤，禁止外站与递归深挖。
7. **画幅与回归**：适用的 16:9 / 1:1 / 9:16 真实渲染保持缩放律；按改动面跑 S11、prompt_gate、pytest/check_gates、render tsc 与 web 测试。定位修复可先跑 `test_film_storyboard_pure.py`、`test_film_dock_storyboard_pure.py`、`test_lifecycle_pure.py`、`test_chat_args_pure.py`，但不得用聚焦套件替代全量仪式链。

### 1.2 正式上线前条件

以下条件全部满足后才可讨论生产启用。只有 §1.1 的真实旅程欠账可以逐条挂账并由用户明确接受；并发、计费授权、有界失败、迁移资源等安全条件不能用“接受残余风险”豁免。**并发发布窗口未关闭时，只能在经验证的隔离演示环境运行，不得宣称多用户正式上线。** 本地门控已开不替代任何一项：

1. **并发发布**：patch 发布的读取→提交窗口经真实竞态演练证明不会覆盖版本，或先实现条件写入/行锁隔离再复跑。注释、低概率和单会话测试不算收口。
2. **计费与授权**：核对双链 hold→capture→release；覆盖新增编辑/变体（若实施）的实际费用、守卫线、不可报价族与 auto/ask 两档制作意图。失败与重试不得重复扣费。
3. **有界失败（R8-M，独立上线条件）**：设计回合必须有共享墙钟与统一 LLM 调用硬上限，schema 修复、多模态降级等嵌套重试不得刷新计数；无进展要停止，系统故障不得交给导演改文案，局部编辑不得发布半稿或改变声明保留范围。当前 1800s 墙钟、候选界和 chat loop 上限已经存在，但**统一 10 次调用硬上限尚未实现**；完整字段级修复 R8-F 可延期，R8-M 不能随之豁免。施工与验收见 §4.3。
4. **迁移与资源**：逐条核对 alembic 链（含 `film_narrations`）、env/flag 默认值、vendored 字体、默认音乐在对象存储与渲染镜像两侧就位；各 flag 与复用 store 有可执行回退路径。
5. **真实旅程、收尾读数与文档**：§1.1 欠账清零或逐条挂账并由用户接受；prompt_gate、剧本矩阵和 S11 网页链按仪式链终跑；记录实际成功/失败、修复轮次、观察指标与成本，不为统计额外扩大探针；当前契约、进度和发布风险一致。
6. **上线后冒烟预案**：双链各一条真实旅程 + 计费台账核对；生产部署仍另行授权。

## 4. 延期项施工合同

### 4.1 R5/R6：宏阶段、恢复与结算（PLANNED）

**范围**：保持 `launch_film` 注册 kind 与报价/出生地/画布归属不变，在编译期展开 `film_prepare` / `film_narrate` / `film_assemble` 内部节点，再接既有 render；`run_review` 的输出归属读取改到链尾。各阶段持久化真实产出，Tasks 只显示真实阶段；内部节点永不暴露为 LLM 工具。flag 默认关闭，单体路径全回归通过后才可在隔离环境启用。

**结算不变量**：capture 唯一座是 assemble 成功；prepare/narrate 只 meter 不 capture；prepare/narrate/assemble 失败均为零 capture，render 失败不退链上已 capture。链累计成本不得重复汇总，报价合计必须与单体公式等价。此合同不改变用户计费政策。

**验收**：编译展开、图形状、出生地门、画布投影、render 认领、`run_review` 链尾读取与报价等价；阶段失败落在真实阶段，恢复不重做上游有效工作；prepare/narrate/assemble/render 四点注入前后对比**净扣费相等、hold 释放/退款相等、无重复收费**（步骤结构可不同，不要求钱包逐行同形）；单体默认路径不回归。R5/R6 全部验收后才切换本地/测试 flag 默认值，并复跑 S11；生产配置和部署仍单独授权。

### 4.2 R8-F：完整字段级修复（PLANNED）

**范围**：保留可解析候选但不发布；`FilmViolation` 携带 scene/field/code/actual/bound；schema `loc` 与语义违例走同一定点通道；模型只返修正字段，系统合入后重查受影响约束与整体一致性。JSON 不可解析才允许有界整篇重生成。系统错误不得交给导演改文案。

**预算与停止**：字段级修复必须复用 §4.3 的统一墙钟与调用计数，不能由嵌套修复重置。相同违例签名重复、签名集无变化或修复倒退时停止并诚实失败。edit ops 继续通过结构化错误回 chat loop，不另建修复平台。

**验收**：分别注入语义违例和“JSON 可解析但单字段不合法”；定点修复成功且未触碰字段字节不变；嵌套重试不重置预算；无进展与系统错误分类正确；不能以调低断言或增加无限重试放行。

### 4.3 R8-M：统一有界预算与保留范围（PLANNED，上线必需）

**当前形态**：1800s 设计墙钟、候选次数、provider/schema/chat loop 各自有界；文字链有无进展早停，Chat Film 设计同签名第 2 次拒绝即停、同回合累计第 3 次设计拒绝必停，编辑原子应用并保留未触碰范围。**缺口**：这些计数尚未汇成设计回合统一的 LLM 生成调用硬上限，不能将“各自有限”或 Film 的每回合失败预算写成统一预算已完成。

**范围**：设计回合共享墙钟与总调用计数，初稿、候选修复、schema 修复、多模态降级等嵌套路径共用同一计数，目标硬上限为 10 次；守卫拒绝和 chat loop 新迭代不得刷新。系统故障直接按系统失败处理，不进入导演文案修复；compose 的既有候选路径可保留，但必须验证声明保留范围，不得通过全稿重写暗改用户要求保留的内容。

**验收**：多层嵌套注入证明计数不重置、超限诚实停止；失败保留范围逐字段不变；双链真实旅程覆盖正常路径与有界失败。若既有候选路径无法达到首发成功率或保留要求，先补必要字段修复，不得以 R8-F 延期为由放出不可用路径。
