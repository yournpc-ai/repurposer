## 0. 为什么做 I8

Repurposer 已经从旧的多渠道内容复用工具，演进为以自然语言操作持续存在的视频工程的 AI 剪辑师。

I1–I7 建立了重要底座：

- Agent 通过 Native Tools 直接编辑 Composition；
- CompositionVersion 保存不可变的作品版本；
- 唯一写口负责原子提交、并发与幂等；
- 预览、真实渲染、Output、授权、费用与恢复已有运行路径；
- 旧 Workflow / Graph / Run 创作执行主线已经退役。

但当前仍存在三类断层：

1. **编辑能力断层：** Composition 和 Renderer 已有部分专业能力，但 Agent 只能使用有限的编辑工具，无法像真人剪辑师一样自由组织素材、图层和动画。
2. **Agent 体验断层：** Prompt 仍有历史任务分类和案例补丁，Chat 的 Tool Call、流式正文、询问、构思和预览尚未形成足够统一的自主编辑体验。
3. **旧产品残留：** Home 默认入口和产品文档已经切换。Persona 深链、Publication、网站来源筛选与历史问答的剩余消费者仍需逐项核查。

I8 不是第三次架构重建。

**I8 的目标是让已有架构真正按照“人类剪辑师的基本工作方式”运行，并退役与这一目标相冲突的旧机制。**

不以功能数量、Tool 数量、Prompt 长度或测试数量作为成果。

## 1. 唯一产品哲学

用户不必学习 DaVinci Resolve、Final Cut Pro、时间线、轨道、关键帧或蒙版操作。

用户只需要提供素材，用自然语言描述想要的效果。

用户说“再往左一点”时，Agent 接着编辑同一份 Working Draft。一次移动、缩放或裁剪都自动保存，暂时遮挡了人物也可继续调。Agent 自选观察时机，可以只说明做了哪些修改。[主合同 §8](new-agent.md#84-停止条件)

高级效果尽量从基本动作组合产生：

- 画中画：多个素材同时显示，调整空间布局、层级和音频；
- 动画与关键帧：对象属性随时间变化；
- 蒙版：限制对象或图层的可见区域；
- 色键与主体抠像：处理素材透明区域，再参与正常合成；
- 复杂动效：多个对象、属性、动画和素材的组合。

**不为每一个效果新建工作流，也不因底层存在某个特效就宣称 Agent 已经能够稳定使用它。**

## 2. 不可破坏的架构边界

保留：

- 唯一 Agent / Native ToolLoop；
- Project、Composition、CompositionVersion；
- Track、Clip、Object、Animation、Keyframe；
- SourceSnapshot、Output；
- `apply_composition_edits` 唯一作品写口；
- MediaJob、ExportJob、Worker 与现有权限、费用、停止及恢复机制；
- `video-spec` 与共享 Remotion 渲染链。

不得引入：

- 第二套 Agent Framework / ToolLoop；
- Plan → DAG → Run / Step 创作执行系统；
- 独立分镜审批引擎；
- 通用 Intent Router 或 Context Manager；
- 第二作品状态或编辑写口；
- 为每种特效分别开发的执行框架；
- 已退役代码的永久兼容层。

允许改造现有结构，但必须证明必要性、明确迁移与消费者，并同步退役被替代的路径。

Worker 负责耗时计算和可靠执行，不取代 Agent 作创作决策。

## 3. 基础编辑动作：先检查最小完备集

I8 优先审计 Agent 是否真正拥有以下操作能力：

| 基本动作 | 含义 |
|---|---|
| Inspect | 读取作品、素材、时间、轨道、对象、属性与动画 |
| Insert | 插入固定素材或新建可编辑对象 |
| Arrange | 组织 Track、Clip 的时间与视觉叠放顺序 |
| Edit | 修改目标对象的布局、变换、样式、透明度、音频等属性 |
| Animate | 创建、修改、移动和删除必要的关键帧 |
| Preview | 播放真实版本的指定范围，观察结果 |
| Revise | 针对观察到的问题继续编辑，保留无关内容 |
| Export / Deliver | 在授权范围内生成、审阅和交付真实 Output |

以上是能力分类，**不是要求逐项新增同名 Tool**。

优先复用现有 `AddTrack`、`AddClip`、`UpdateClip`、时间编辑操作、动画求值器和唯一写口。新增 Native Tool 应根据实际调用需求设计。

避免把底层 `tick`、复杂对象 JSON 和脆弱像素计算直接交给模型猜测。必要时由工具将秒数、相对位置、安全边界等映射到合法领域参数。

现有 `Track.order` 已有叠放语义。除非源码证明必要，不再给 Object 叠加第二套互相冲突的 Z 顺序。

所有新增操作必须保持对象身份、素材引用、既有动画和无关内容。

## 4. 高级合成的正确位置

I8 不预先承诺实现完整 NLE 或全部专业特效。

对能力缺口分类处理：

**已有底层表达能力，Agent 尚不能直接操作：** 优先完善原生编辑 Tool。

**现有模型无法表达：** 在 Composition / video-spec / Renderer 中做最小必要扩展。

**素材本身需要计算：** 复用现有异步媒体执行机制，将固定结果作为可引用素材，再由 Agent 进行编辑。

需要特别区分：

- 形状对象不等于能够裁切另一个视频的 Mask；
- 绿幕色键不必然需要独立 AI 推理；
- 无绿幕视频主体抠像可能需要额外的模型、时序处理及透明素材；
- 代码生成或烘焙成片不等于内部图层可持续精确编辑。

**优先保留作品的可编辑性，不为一次成功的视觉演示牺牲后续自然语言修订能力。**

抠像与色键都是长期目标，具体先后由技术证据和真实任务决定。

## 5. Agent 自主权与 Ask User

Agent 在当前稿上自主选择对象和连续动作，需要判断效果时可随时预览。用户指定先看再改时遵守该顺序；关键歧义、目标变更与额外费用交给用户决定。

Agent 应先读取已有事实和可用能力，尽量自行解决非关键的不确定性。

用户要求模糊，但可基于现有作品合理判断时，直接执行合适的操作。

例如：“让这段视频更有动感。”Agent 可以先查看镜头，从节奏或运动入手，预览并修订。

仅在以下情况询问用户：

- 关键对象无法确定，猜错会改变实质目标；
- 用户希望先选择创作方向；
- 需要改变用户核心要求；
- 需要未经授权的新素材制作；
- 需要额外费用确认；
- 存在无法通过读取和检查解决的必要信息缺口。

一次只问最重要的阻塞问题。

用户明确要求先给方案时，不擅自开工。

**Ask User 是 Agent 的一种行为，不是统一工作流程的必经阶段。**

## 6. 分镜与创作构思

分镜是沟通形式，不是执行协议。

复杂、多镜头、叙事型创作，Agent 可以简洁表达镜头设计；明确的局部修改直接操作，不强制出分镜。

分镜可以包含：

- 镜头序号、时间范围；
- 主体、环境；
- 构图和镜头运动；
- 风格、色调、灯光；
- 必要的技术参数和保持条件。

这些是可选的创作描述维度，不是每镜头必须填写的字段。

用户端优先用现有 Chat Markdown 与媒体附件组合，按需展示真实素材截图或已有画面，配少量描述。禁止重新建设长表格审批、Plan 状态或强制分镜确认机制。

Agent 可以边工作边解释镜头构思。用户没有要求停下来确认时，不因展示构思而打断正常 ToolLoop。

分镜文字不能成为第二套作品事实，也不能自动升级为用户硬要求。

## 7. Prompt / Context：少规则，真实事实

Prompt 的职责是让 Agent 成为可靠的剪辑师，而不是把历史事故逐项写成操作手册。

稳定核心原则：

> 你是一名专业 AI 视频剪辑师。理解用户目标与当前作品，检查必要事实，使用可用的原生工具自主编辑。优先保留已有素材、可编辑结构及用户未要求改变的内容。信息足够时直接行动；关键目标或授权不明确时询问一个必要问题。复杂创作可简洁说明构思，但不强制先分镜。自主选择观察时机，用实际收到的媒体判断效果和修订方向。无法完成时检查可用能力，说明真实限制与替代方案，未经许可不改变用户目标或进行额外付费制作。只根据实际执行与观察结果报告完成状态。

上述文字是**设计意图**，不是要求逐字覆盖现役 System Prompt。

Context 只提供本轮有用的事实：

- 当前用户目标与明确约束；
- 当前稿、所选对象、已经保存的动作；版本与 digest 供工具核对写入基线；
- 相关素材、轨道、对象和动画；
- 最近真实观察和执行回执；
- 授权、费用、历史 Output 与待完成事项。

创作新镜头时，可使用主体、环境、构图、运镜、风格、色调、参数等专业知识。

编辑已有镜头时，优先使用目标、时间、修改属性与保持条件。

审片时，优先使用用户目标、实际画面和证据覆盖范围。

不要求每轮都填写六维提示词，不新建专门的意图路由系统。

确定性约束应位于 Tool Schema、领域 Validator 或权限/费用服务中；Prompt 负责决策与诚实报告。

失败修复必须首先区分：缺 Tool、Context 错误、Schema 不清晰、模型选错、Renderer 错误，还是观察不足。不得习惯性向 System Prompt 追加案例规则。

## 8. Chat UI：用户看到工作、修改与结果

沿用现有 AffectUI + Tailwind + Motion 与 Chat-First 交互，不重建重型时间线/Canvas。

一次位移可以只显示真实编辑 Activity 和已保存的结果。用户要播放或导出时，在同一 Chat 提供对应的窗口或正式文件。

要求：

- Activity 来自真实工具执行状态；
- 用户读得懂“检查素材、调整画面、设置运动、正在预览”；
- 不把内部 tick、数据库 ID、完整参数 JSON 当作主界面；
- 必要时可展开具体操作细节以便诊断；
- Tool Call 失败不得被动画或正文包装成成功；
- 预览必须对应准确版本与真实媒体；
- 分镜只在有帮助时出现；
- 用户可以通过时间、画面选区和自然语言继续指认修改目标；
- Live、刷新、Stop、恢复后的历史展示一致；
- 正文必须区分已编辑、已预览、已导出、已交付和目标已满足。

Motion 负责连续、克制的状态表达，不得虚构工作进度。

**UI 不需要模拟剪辑师手动拖轨道的全部过程，而要清楚展示 Agent 正在做什么及实际结果。**

## 9. 自主探索、权限与费用

Agent 可以查找素材、检查系统工具、读取专业方法，并在可用能力不足时探索替代方案。

不得：

- 擅自改变用户核心目标；
- 将近似效果称为精确完成；
- 未经必要授权生成新的付费素材；
- 绕过现有账户权限、费用及隐私边界；
- 因为存在 Output 就宣称用户要求全部满足。

**允许真实付费执行与验证。**

施工与验收可以使用真实 LLM、视频生成、图像生成、配音、Renderer、存储和已授权的相关服务。不得为了避免费用而把 Mock 结果充当正式通过。

执行必须遵守既有授权门与测试预算，控制无效重试，记录模型、请求次数、Token、媒体费用、积分、Job 和最终结果。不得无限制消耗。

费用是否值得，应按**成功完成一次用户任务的总成本**评估，而不是只看一次模型调用价格。

## 10. 旧 Repurposer 残留退役

旧残留清理是 I8 的正式目标，不是可选文档卫生。

必须核查：

- README、CLAUDE、PRD、JOURNEYS、docs/README 的产品定位与错误事实；
- Home 示例、Recipe、Persona / SkinEditor、旧编辑器与历史 Canvas；
- Agent Prompt、readiness、Brief、网站特化分类与隐藏 Tool 门控；
- 内置和外部 Skill 的方法、默认约束及工具访问；
- 旧图文输出、Distribution、Channels / Publications 的真实消费者；
- 旧 Workflow / Run / Graph 的代码引用、数据结构及实际调用；
- 根目录临时文件、scratch、artifacts 与历史验收证据。

对每项残留给出：

**位置 → 当前消费者 → 是否影响现役产品 → 保留/收窄/重写/冻结/删除 → 回归风险 → 退役证明。**

原则：

1. 新剪辑哲学取代的旧创作机制，必须真正退役。
2. 新旧消费者切换在同一切片完成，不留下永久兼容层。
3. `plan_turn.py` 或 `pipeline/` 的旧名称本身不是删除依据；现役 ToolLoop、Worker、MediaJob、ExportJob 必须保护。
4. Output 观看、MediaLightbox 选区、历史版本与真实费用记录是新产品的有用基础能力。
5. 不能为清理旧产品而删除真实用户作品、素材、历史交付或不可恢复的业务数据。
6. Persona、分发等仍有消费者的模块，先查依赖，再作有证据的处置判断；不得擅自破坏用户资料。

最终目标不仅是代码不再运行旧 Workflow，还包括**现行文档、模型上下文和用户入口不再把产品引回旧多渠道内容复用工具**。

## 11. 施工组织：两条主线，一套闭环

I8 有两类施工内容：

**A. 专业编辑能力与 Agent 体验**

围绕基础操作、Prompt/Context、Chat UI、预览与恢复形成最小完整切片。

**B. 旧产品与执行残留退役**

围绕实际消费者逐项物理减法、迁移或收窄。

A、B 不是两套运行架构。

一个新能力替代了某项旧机制时，尽量在同一施工切片中完成新路径、消费者切换、旧路径删除和回归。

不得先开发全部后端，再独立开发全部前端，最后才接 Prompt。

首个切片及其退出条件见 §13。后续只按真实任务暴露的下一处缺口立项。

## 12. 五面一体验收

从真实 Chat 核对同一 opening 中的五面事实。合法修改可以直接保存并如实结束；模型观察、修订或正式导出时，再核对该动作的媒体、判断或交付回执。[A–G 验收维度](../VERIFICATION.md#12-当前验证层)

| 面 | 必须证明 |
|---|---|
| Tool | 模型实际可见 Schema、正确调用、参数合法、真实执行 |
| Prompt / Context | 用户目标、版本、素材、对象、观察和授权事实正确 |
| Chat | Activity、流式正文、询问、可选分镜、预览和交付真实一致 |
| Execution / State | 修改自动保存，无关对象及引用保持；涉及 Renderer 或交付时另验实际音画 |
| Recovery / Replay | Stop、重放、并发、必要故障注入不会重复编辑或收费 |

每批报告继续遵守 `new-agent.md` §12 的 Git/现场、五面和结论七部分结构。

验收样本至少应覆盖：

- 模糊但可行动的用户目标；
- 真正阻塞的对象歧义；
- 简单局部编辑直接执行；
- 复杂多镜头任务按需展示构思；
- 纯效果语言和半专业术语执行同一能力；
- 两轮连续编辑，保留无关内容与音频；
- 新增对象、动画与已有版本的正确关系；
- 真实 Web 预览与正式 MP4 一致；
- 当前能力不足时如实解释；
- 费用确认、Stop、刷新、重试和必要的编辑中强杀恢复。

首次盲测、修复后复测、新素材测试和回归测试分开统计。

必须分别判断：

1. Tool 是否合法、准确地修改了指定内容；
2. Agent 是否能按需观察、判断并修订；
3. 回合正文是否如实说明实际结果、观察与限制；
4. 正式交付的文件、费用与恢复是否可靠。

禁止只用 Mock、Schema 合法率、测试数量或同一 Demo 的重复成功宣布整批通过。

## 13. I8-0 源码裁决与施工交接（施工前基线）

2026-11-22，核查基线为本地及远端 main 的 `ebf50607ee2f9265b17e88cc43a03a5f0e1ac2f8`，接手时工作树干净。本节的“通过”限于可从该版本确认的调用关系或注明的历史样本。本轮未运行模型、浏览器、Worker 或生产数据查询。领域依据见 [Chat](../CHAT_ARCHITECTURE.md)、[作品](../VIDEO_PROJECT.md)、[编辑](../VIDEO_EDITOR.md)、[渲染](../RENDERING.md)、[账本](../BILLING.md) 和 [验证](../VERIFICATION.md)。

### 实际入口与首要异议

下文后端短路径相对 `apps/api/app/`，前端组件相对 `apps/web/src/`。从一次真实 opening 看，`chat/routes.py → service.py → plan_turn.run_plan_turn → prompts.assemble_video_round → agents/tool_loop.py` 才决定模型实收的工具和观察。ToolLoop 按装配结果向 Provider 提供 Schema，PlanTurn 将调用分派给 editor、素材准备或感知工具。普通编辑经 `editor.execute_editor → edit_clip → editing/store.apply_composition_edits` 保存版本，再将变动对象投回下一轮。声明到 `EDITOR_TOOLS` 只是第一步。

**最重要的设计冲突发生在每轮装配。** 已选作品可以列素材，然而 `prepare_video_materials`、`get_asset` 只在 native_creation 分支加入。编辑做了一步或收到预览后，`prompts.py` 又移除 `ask_user`，即使下一步才遇到歧义。与此同时，模型会收到人脸边框、像素留边、配音绑定和导出续行等一整段规则。只改 `prompts/chat/system.j2` 无法修正实际发送的请求。相反，旧版冲突、来源权限、付费授权以及已授权导出的固定文件续行均有真实约束，应继续硬校验。

常驻原则可收为：“围绕用户这次要改的内容工作。先定位素材和版本，可行动就编辑，阻塞才问。保留未点名的内容。观察相同时间窗，根据看见或听见的结果修订。只在许可内制作并如实交付。” 把坐标、时间域、来源和观察边界放回相应 Tool 的描述或回执。模型自行决定是否提出构思。改动前后保存**实际 Provider 载荷**，复测 I7 的裁字、露底与局部播放误报价样本，另测模型没有收到声音时是否仍评价听感。

**为什么先做插图。** 单一局部任务同时检验项目素材能否进入已有工程、层级和对象是否可寻址、观察后能否在同一对象上继续改。把精力投入重做时间线、预设或关键帧求值器，无法解决这三件事。首片只接一张仍可编辑的图，不承诺视频混音、蒙版、色键或分割推理。

**真实验收与成本。** 隔离项目中用获准公开的自录/合成 6 秒产品演示 MP4（可辨背景动作和原声）、底部原生字幕、带可读标记的非方形产品 PNG。素材从真实上传入口进入，记录原件 hash。盲测操作只给原句和附件；用另一种比例的新图与“叠图/画中画”表述独立复测，另测两个同名附件的阻塞问题。保留每次首次失败，修后重测另计。核对完整受影响窗口的解码帧、位置和比例，窗外原画、字幕和时长不变；真实试听与模型是否收到了声音分别记录。打开历史窗口、续签、硬刷新及下载，对照同一版本、Output 和文件 hash。

建议本批测试预算上限为 3 次短片导出（首测、新素材、一次归因后复测），总计最多 60 积分、模型会话计量最多 1 美元。此为建议限额，执行取现有授权与建议上限的较低值。每次入队前核对真实账户报价，每轮请求核对累计用量；拒绝或 Stop 用例不追加付费导出。未覆盖的报价先取额外授权；重复调用、供应商状态未知或超出批准预算时停在原回执。记录模型和请求数、输入/输出/缓存 Token、会话计量、预览次数、每次 Job/认领/报价/预占/实扣/释放、opening、版本、Output 与失败开销，分别报告成功样本成本及含失败的总成本。I7 实际合计 **284 积分**，最终两条成功旅程 **139 积分**，会话计量 **0.319653 美元**（未取得供应商最终账单）；不可据此保证 I8 单价。正式导出用公开 TOS，真实私有作品不能直接拿来跑该样本。

## 14. 完成标准

用户能在同一 Chat 持续修改当前影片。一次编辑回合可以交回已保存的改动、实际看过的效果，或清楚说明未完成的目标。按用户请求分别签收草稿、播放和正式交付；后台历史用于核对写入、恢复与旧成片引用。

### 15.2 最小施工顺序（待审批）

1. **持久事实收尾（P0）。** `PlanTurn.finish` 的无进展分支和 `_loop_incomplete_text` 的预算耗尽分支都可能在成功写入后触发。沿用 `report_committed_edits` 按 opening、request、owner/project 查询已提交历史的读法，结合真实调用与提交前后目标字段说明改了什么；同时读取当前稿、待处理授权或 Job、旧 Output。只复用读面，保留恢复函数的 Activity 修复和中断消息在原入口。生成一次持久正文供 Live 和 Replay 使用。对本次片尾应能说清“字幕已延长半秒，主画面没有延长，旧成片仍可播放，可以从当前稿继续”。这条结论只需编辑事实，无需声称看见黑场。
2. **轻量 Finish。** 沿用自然正文和 `answer`。在现有 `assemble_video_round` 中用动作、对象描述当前稿，将 base 和编号留给工具。把本轮已保存的动作和实际返回的媒体说清楚，供两种答复共用；调整 `preview_range` 的工具描述，保留用户指定窗口，允许 Agent 自选接缝。只改了位置即可报告位置已改；想判断遮挡时由 Agent 自行预览。工具和宿主只从回执生成活动、播放组件与交付状态。自由正文的任意语义无法由工具回执自动验证，使用实际模型输入和 Chat 样本检查“看过、听过、已交付”等误述；没有观察即可明说效果尚未确认。使用现有答复参数和预算，Finish 不触发渲染。
3. **定向复测。** 在少数[真实 Chat 旅程](../VERIFICATION.md#12-当前验证层)中覆盖两个切片。优先复现字幕已保存后的停止，核对 Live、刷新与旧 Output；另测未预览的合法结束，以及 Agent 自选局部观看后继续修改。复用已签收的 Renderer、固定成片、费用和恢复证据。
