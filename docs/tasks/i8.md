# I8 · 专业 AI 剪辑师：基础动作、Agent 体验与旧体系退役

**状态：设计与施工候选合同，具体切片须经源码对账后冻结**

**上位合同：** `docs/tasks/new-agent.md`  
**进度事实：** `docs/PROGRESS.md` §0  
**核心原则：大道至简、一通百通、不破不立、五面一体、真实验收。**

---

## 0. 为什么做 I8

Repurposer 已经从旧的多渠道内容复用工具，演进为以自然语言操作持续存在的视频工程的 AI 剪辑师。

I1–I7 建立了重要底座：

- Agent 通过 Native Tools 直接编辑 Composition；
- CompositionVersion 保存不可变的作品版本；
- 唯一写口负责原子提交、并发与幂等；
- 预览、真实渲染、Output、授权、费用与恢复已有运行路径；
- 旧 Workflow / Graph / Run 创作执行主线已经退役。

但当前仍存在三类断层：

1. **编辑能力断层：** Composition 和 Renderer 已有部分专业能力，但 Agent 只能使用有限的编辑工具，无法像真人剪辑师一样自由组织素材、图层和动画。
2. **Agent 体验断层：** Prompt 仍有历史任务分类和案例补丁，Chat 的 Tool Call、流式正文、询问、构思和预览尚未形成足够统一的自主编辑体验。
3. **旧产品残留：** README、PRD、JOURNEYS、Home、Persona、部分 Skill 与专用逻辑仍可能将开发者、Agent 或用户引回旧 Repurposer。

I8 不是第三次架构重建。

**I8 的目标是让已有架构真正按照“人类剪辑师的基本工作方式”运行，并退役与这一目标相冲突的旧机制。**

不以功能数量、Tool 数量、Prompt 长度或测试数量作为成果。

## 1. 唯一产品哲学

用户不必学习 DaVinci Resolve、Final Cut Pro、时间线、轨道、关键帧或蒙版操作。

用户只需要提供素材，用自然语言描述想要的效果。

Agent 像真人剪辑师一样：

**理解目标 → 检查作品和素材 → 插入与组织素材 → 修改属性和动画 → 播放观察 → 继续修订 → 保存与交付。**

这是持续循环，不是固定阶段流水线。

高级效果尽量从基本动作组合产生：

- 画中画：多个素材同时显示，调整空间布局、层级和音频；
- 动画与关键帧：对象属性随时间变化；
- 蒙版：限制对象或图层的可见区域；
- 色键与主体抠像：处理素材透明区域，再参与正常合成；
- 复杂动效：多个对象、属性、动画和素材的组合。

**不为每一个效果新建工作流，也不因底层存在某个特效就宣称 Agent 已经能够稳定使用它。**

## 2. 不可破坏的架构边界

保留：

- 唯一 Agent / Native ToolLoop；
- Project、Composition、CompositionVersion；
- Track、Clip、Object、Animation、Keyframe；
- SourceSnapshot、Output；
- `apply_composition_edits` 唯一作品写口；
- MediaJob、ExportJob、Worker 与现有权限、费用、停止及恢复机制；
- `video-spec` 与共享 Remotion 渲染链。

不得引入：

- 第二套 Agent Framework / ToolLoop；
- Plan → DAG → Run / Step 创作执行系统；
- 独立分镜审批引擎；
- 通用 Intent Router 或 Context Manager；
- 第二作品状态或编辑写口；
- 为每种特效分别开发的执行框架；
- 已退役代码的永久兼容层。

允许改造现有结构，但必须证明必要性、明确迁移与消费者，并同步退役被替代的路径。

Worker 负责耗时计算和可靠执行，不取代 Agent 作创作决策。

## 3. 基础编辑动作：先检查最小完备集

I8 优先审计 Agent 是否真正拥有以下操作能力：

| 基本动作 | 含义 |
|---|---|
| Inspect | 读取作品、素材、时间、轨道、对象、属性与动画 |
| Insert | 插入固定素材或新建可编辑对象 |
| Arrange | 组织 Track、Clip 的时间与视觉叠放顺序 |
| Edit | 修改目标对象的布局、变换、样式、透明度、音频等属性 |
| Animate | 创建、修改、移动和删除必要的关键帧 |
| Preview | 播放真实版本的指定范围，观察结果 |
| Revise | 针对观察到的问题继续编辑，保留无关内容 |
| Export / Deliver | 在授权范围内生成、审阅和交付真实 Output |

以上是能力分类，**不是要求逐项新增同名 Tool**。

优先复用现有 `AddTrack`、`AddClip`、`UpdateClip`、时间编辑操作、动画求值器和唯一写口。新增 Native Tool 应根据实际调用需求设计。

避免把底层 `tick`、复杂对象 JSON 和脆弱像素计算直接交给模型猜测。必要时由工具将秒数、相对位置、安全边界等映射到合法领域参数。

现有 `Track.order` 已有叠放语义。除非源码证明必要，不再给 Object 叠加第二套互相冲突的 Z 顺序。

所有新增操作必须保持对象身份、素材引用、既有动画和无关内容。

## 4. 高级合成的正确位置

I8 不预先承诺实现完整 NLE 或全部专业特效。

对能力缺口分类处理：

**已有底层表达能力，Agent 尚不能直接操作：** 优先完善原生编辑 Tool。

**现有模型无法表达：** 在 Composition / video-spec / Renderer 中做最小必要扩展。

**素材本身需要计算：** 复用现有异步媒体执行机制，将固定结果作为可引用素材，再由 Agent 进行编辑。

需要特别区分：

- 形状对象不等于能够裁切另一个视频的 Mask；
- 绿幕色键不必然需要独立 AI 推理；
- 无绿幕视频主体抠像可能需要额外的模型、时序处理及透明素材；
- 代码生成或烘焙成片不等于内部图层可持续精确编辑。

**优先保留作品的可编辑性，不为一次成功的视觉演示牺牲后续自然语言修订能力。**

抠像与色键都是长期目标，具体先后由技术证据和真实任务决定。

## 5. Agent 自主权与 Ask User

默认自主完成创作。

Agent 应先读取已有事实和可用能力，尽量自行解决非关键的不确定性。

用户要求模糊，但可基于现有作品合理判断时，直接执行合适的操作。

例如：“让这段视频更有动感。”Agent 可以先查看镜头，从节奏或运动入手，预览并修订。

仅在以下情况询问用户：

- 关键对象无法确定，猜错会改变实质目标；
- 用户希望先选择创作方向；
- 需要改变用户核心要求；
- 需要未经授权的新素材制作；
- 需要额外费用确认；
- 存在无法通过读取和检查解决的必要信息缺口。

一次只问最重要的阻塞问题。

用户明确要求先给方案时，不擅自开工。

**Ask User 是 Agent 的一种行为，不是统一工作流程的必经阶段。**

## 6. 分镜与创作构思

分镜是沟通形式，不是执行协议。

复杂、多镜头、叙事型创作，Agent 可以简洁表达镜头设计；明确的局部修改直接操作，不强制出分镜。

分镜可以包含：

- 镜头序号、时间范围；
- 主体、环境；
- 构图和镜头运动；
- 风格、色调、灯光；
- 必要的技术参数和保持条件。

这些是可选的创作描述维度，不是每镜头必须填写的字段。

用户端优先采用简洁图文镜头卡：真实素材截图或已有画面 + 少量关键描述。禁止重新建设长表格审批、Plan 状态或强制分镜确认机制。

Agent 可以边工作边解释镜头构思。用户没有要求停下来确认时，不因展示构思而打断正常 ToolLoop。

分镜文字不能成为第二套作品事实，也不能自动升级为用户硬要求。

## 7. Prompt / Context：少规则，真实事实

Prompt 的职责是让 Agent 成为可靠的剪辑师，而不是把历史事故逐项写成操作手册。

稳定核心原则：

> 你是一名专业 AI 视频剪辑师。理解用户目标与当前作品，检查必要事实，使用可用的原生工具自主编辑。优先保留已有素材、可编辑结构及用户未要求改变的内容。信息足够时直接行动；关键目标或授权不明确时询问一个必要问题。复杂创作可简洁说明构思，但不强制先分镜。修改后根据实际预览判断是否需要继续修订。无法完成时检查可用能力，说明真实限制与替代方案，未经许可不改变用户目标或进行额外付费制作。只根据实际执行与观察结果报告完成状态。

上述文字是**设计意图**，不是要求逐字覆盖现役 System Prompt。

Context 只提供本轮有用的事实：

- 当前用户目标与明确约束；
- 当前作品、版本、选中的目标；
- 相关素材、轨道、对象和动画；
- 最近真实观察和执行回执；
- 授权、费用、历史 Output 与待完成事项。

创作新镜头时，可使用主体、环境、构图、运镜、风格、色调、参数等专业知识。

编辑已有镜头时，优先使用目标、时间、修改属性与保持条件。

审片时，优先使用用户目标、实际画面和证据覆盖范围。

不要求每轮都填写六维提示词，不新建专门的意图路由系统。

确定性约束应位于 Tool Schema、领域 Validator 或权限/费用服务中；Prompt 负责决策与诚实报告。

失败修复必须首先区分：缺 Tool、Context 错误、Schema 不清晰、模型选错、Renderer 错误，还是观察不足。不得习惯性向 System Prompt 追加案例规则。

## 8. Chat UI：用户看到工作、修改与结果

沿用现有 AffectUI + Tailwind + Motion 与 Chat-First 交互，不重建重型时间线/Canvas。

一个典型编辑过程应当呈现：

**真实 Activity / Tool Call → 简洁流式正文 → 必要时的镜头卡或真实预览 → 后续修订 → 交付。**

要求：

- Activity 来自真实工具执行状态；
- 用户读得懂“检查素材、调整画面、设置运动、正在预览”；
- 不把内部 tick、数据库 ID、完整参数 JSON 当作主界面；
- 必要时可展开具体操作细节以便诊断；
- Tool Call 失败不得被动画或正文包装成成功；
- 预览必须对应准确版本与真实媒体；
- 分镜只在有帮助时出现；
- 用户可以通过时间、画面选区和自然语言继续指认修改目标；
- Live、刷新、Stop、恢复后的历史展示一致；
- 正文必须区分已编辑、已预览、已导出、已交付和目标已满足。

Motion 负责连续、克制的状态表达，不得虚构工作进度。

**UI 不需要模拟剪辑师手动拖轨道的全部过程，而要清楚展示 Agent 正在做什么及实际结果。**

## 9. 自主探索、权限与费用

Agent 可以查找素材、检查系统工具、读取专业方法，并在可用能力不足时探索替代方案。

不得：

- 擅自改变用户核心目标；
- 将近似效果称为精确完成；
- 未经必要授权生成新的付费素材；
- 绕过现有账户权限、费用及隐私边界；
- 因为存在 Output 就宣称用户要求全部满足。

**允许真实付费执行与验证。**

施工与验收可以使用真实 LLM、视频生成、图像生成、配音、Renderer、存储和已授权的相关服务。不得为了避免费用而把 Mock 结果充当正式通过。

执行必须遵守既有授权门与测试预算，控制无效重试，记录模型、请求次数、Token、媒体费用、积分、Job 和最终结果。不得无限制消耗。

费用是否值得，应按**成功完成一次用户任务的总成本**评估，而不是只看一次模型调用价格。

## 10. 旧 Repurposer 残留退役

旧残留清理是 I8 的正式目标，不是可选文档卫生。

必须核查：

- README、CLAUDE、PRD、JOURNEYS、docs/README 的产品定位与错误事实；
- Home 示例、Recipe、Persona / SkinEditor、旧编辑器与历史 Canvas；
- Agent Prompt、readiness、Brief、网站特化分类与隐藏 Tool 门控；
- 内置和外部 Skill 的方法、默认约束及工具访问；
- 旧图文输出、Distribution、Channels / Publications 的真实消费者；
- 旧 Workflow / Run / Graph 的代码引用、数据结构及实际调用；
- 根目录临时文件、scratch、artifacts 与历史验收证据。

对每项残留给出：

**位置 → 当前消费者 → 是否影响现役产品 → 保留/收窄/重写/冻结/删除 → 回归风险 → 退役证明。**

原则：

1. 新剪辑哲学取代的旧创作机制，必须真正退役。
2. 新旧消费者切换在同一切片完成，不留下永久兼容层。
3. `plan_turn.py` 或 `pipeline/` 的旧名称本身不是删除依据；现役 ToolLoop、Worker、MediaJob、ExportJob 必须保护。
4. Output 观看、MediaLightbox 选区、历史版本与真实费用记录是新产品的有用基础能力。
5. 不能为清理旧产品而删除真实用户作品、素材、历史交付或不可恢复的业务数据。
6. Persona、分发等仍有消费者的模块，先查依赖，再作有证据的处置判断；不得擅自破坏用户资料。

最终目标不仅是代码不再运行旧 Workflow，还包括**现行文档、模型上下文和用户入口不再把产品引回旧多渠道内容复用工具**。

## 11. 施工组织：两条主线，一套闭环

I8 有两类施工内容：

**A. 专业编辑能力与 Agent 体验**

围绕基础操作、Prompt/Context、Chat UI、预览与恢复形成最小完整切片。

**B. 旧产品与执行残留退役**

围绕实际消费者逐项物理减法、迁移或收窄。

A、B 不是两套运行架构。

一个新能力替代了某项旧机制时，尽量在同一施工切片中完成新路径、消费者切换、旧路径删除和回归。

不得先开发全部后端，再独立开发全部前端，最后才接 Prompt。

### 切片确定原则

每个切片只解决一个清楚的真实用户能力缺口，但必须拥有完整五面闭环。

候选顺序：

1. 现役架构与旧消费者事实对账；
2. Agent 自主行动、Ask User、按需分镜的行为收口；
3. 插入素材、安排图层、修改空间和音频属性的真实编辑任务；
4. 创建及连续修订必要关键帧；
5. 最小几何蒙版与多层组合任务；
6. 色键与主体抠像的技术验证及后续切片。

这只是研究顺序，**不是预先冻结 I8 的开发功能清单**。

不得以“大道至简”为借口跳过实际缺失的计算与渲染能力，也不得为某个 Demo 再建特化工作流。

## 12. 五面一体验收

每个施工切片都必须同时证明：

| 面 | 必须证明 |
|---|---|
| Tool | 模型实际可见 Schema、正确调用、参数合法、真实执行 |
| Prompt / Context | 用户目标、版本、素材、对象、观察和授权事实正确 |
| Chat | Activity、流式正文、询问、可选分镜、预览和交付真实一致 |
| Execution / State | 正确保存版本与媒体，Renderer 正确，音画与无关内容保持 |
| Recovery / Replay | Stop、重放、并发、必要故障注入不会重复编辑或收费 |

每批报告继续遵守 `new-agent.md` §12 的 Git/现场、五面和结论七部分结构。

验收样本至少应覆盖：

- 模糊但可行动的用户目标；
- 真正阻塞的对象歧义；
- 简单局部编辑直接执行；
- 复杂多镜头任务按需展示构思；
- 纯效果语言和半专业术语执行同一能力；
- 两轮连续编辑，保留无关内容与音频；
- 新增对象、动画与已有版本的正确关系；
- 真实 Web 预览与正式 MP4 一致；
- 当前能力不足时如实解释；
- 费用确认、Stop、刷新、重试和必要的编辑中强杀恢复。

首次盲测、修复后复测、新素材测试和回归测试分开统计。

必须分别判断：

1. 作品是否正确；
2. Agent 的判断与陈述是否正确；
3. 交付是否可靠。

禁止只用 Mock、Schema 合法率、测试数量或同一 Demo 的重复成功宣布整批通过。

## 13. I8-0：开工前的必需交付

先完成只读源码对账，并修订本合同。

交付三份有限、可执行的清单：

**A. 基础编辑能力差距表**

当前数据模型 → 现役 Tool → Renderer → 真实验证 → 最小缺口。

**B. 旧残留退役表**

位置 → 消费者 → 处置 → 依赖风险 → 回归证明。

**C. 五面施工切片表**

用户任务 → 需要修改的实际代码面 → Tool/Context/Chat/Execution/Recovery 验收 → 付费预算与成功标准。

每一项建议必须以现役源码、真实用户体验或已有失败证据为依据。

不得为了完整而制造不必要的系统、文档、组件或抽象。

## 14. 完成标准

I8 的成功不是交付一个更大的 Tool Registry 或更复杂的 Agent UI。

而是让一个从未见过该工程的用户，用自然语言要求 Agent 操作视频，并能够持续看到：

**它理解目标 → 正确编辑 → 实际看片 → 自主纠错 → 不破坏旧内容 → 如实交付。**

同时，新接手仓库的开发者和 Agent 不会再被旧 Repurposer 的产品描述与执行协议误导。

**先把这一件事做好，然后所有高级剪辑能力都应沿同一个循环自然增长。**
