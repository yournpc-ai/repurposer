# POSITIONING — 定位根概念架构（运营层母文档）

> Status: 已拍板方向（2026-08-13，ADR-042），**未实施**。施工排期见 PROGRESS §2 第六~八周（生产层闭环收口后动工）。
> 本文是「定位 / 人设 / 渠道 / 选题」概念架构的**唯一事实源**；其他文档只引用，不复述。落地前，现状身份模块的事实源仍是 `MODULE_ARCHITECTURE.md`「Memory / Context」层 + ADR-037/038；第一刀落地时本文转为现状事实源，上述入口同步改写。

## 1. 一句话裁决

**身份根 = 定位（`positioning`），多实例（工作号/生活号 = 两个定位）。** 人设收窄为定位的表达分区；渠道、选题、素材挂根；品牌/IP 留在营销承诺层，不进产品内概念。

## 2. 为什么 persona 撑不起来（问题陈述）

三个概念的现状病灶：

- **定位缺位**：策略三件（`audience` / `guidelines` / `cta`）只是定位的薄切片，因无处安放而寄存人设。agent 顾问姿态诊断（听众/目的）问完没有落点，"用户到来即彷徨"（STRATEGY §5）没有持久答案。
- **渠道空壳**：`channel_accounts` 只是 OAuth token 的容器——不知道自己属于谁、服务哪个受众、默认什么语言；发布数据回流（P2）将无处可挂。
- **人设被偷渡**："多实例扁平（工作号/生活号）"实为**两个定位**被压成两行风格对象——不同受众、不同疆域、不同渠道，却共享不到任何东西，同一真人要克隆两次声纹。

更深一层：**定位和人设是两种来源、两种生命周期的东西**——

| | 定位 | 人设 |
|---|---|---|
| 本质 | **选择**（对谁说、说什么、凭什么） | **特征**（怎么写、怎么听起来/看起来） |
| 来源 | 素材里没有答案，只能**对话共建**：agent 提议、用户拍板、带确认环节 | 素材里挖出来：**自动提取**（bootstrap 已证明可行）、用户只在"不像我"时修 |
| 页面角色 | 接待处（首轮对话的产物） | 维修点（产物不像我时才来） |

混在一个对象里，页面就既想当接待处又想当维修点，两边都不讨好。**定位在上、人设在下，不是谁大谁小——说什么定了，才知道该怎么说。**

两条外部佐证：

- **行业话语**：自媒体新人听到的第一句话是"找定位"，不是品牌相关的话；且行业标准用法里定位天然三分——**内容定位 + 人设定位 + 平台定位**，定位 ⊇ 人设。
- **运营全链路对照**（小红书运营链：定位 → 账号 → 对标 → 选题库 → 标题/文案/封面/视频）：现有架构只覆盖生产层（素材 → 任务书 → 技能 → 产物）+ 发布；运营层——持续回答"该做什么"的那一半——整体缺失。

## 3. 概念架构

```
Positioning（定位 = 根，多实例）
├── identity    身份卡：名字 / 头衔 / 头像 / 简介 / 语言        （我是谁）
├── strategy    内容定位：疆域 / 受众 / 差异化 / 目标 / 边界     （说什么、对谁说、为什么说）
│               = territory / audience / differentiation / goals / guidelines / cta
├── persona     人设定位：风格六件 + voice 块（声纹）+ brand 块（皮肤）（怎么呈现——原 personas 表内容原样保留）
├── channels[]  平台定位：channel_accounts 挂根                 （在哪发）
├── topics[]    选题库：内容定位长出的运营中枢                  （下一条做什么）
└── assets[]    素材档案：从项目/人设上提到根                   （选题的矿）
```

各分区职责：

| 分区 | 职责 | 写入方式 |
|---|---|---|
| identity | 身份卡（LinkedIn headline 语义） | 用户编辑 / 首轮对话起草 |
| strategy（内容定位） | agent 一切"该做什么"判断的依据：选题生成、任务书构建、首发推荐、回流校准的靶子 | **对话共建带确认**（诊断一轮封顶，只问用户能答的） |
| persona（人设定位） | 表达层：director 系 prompt 注入 / 声纹 dub / 皮肤烘焙，全部现状机制不动 | **素材提取 + 维修点编辑**（现状机制不动） |
| channels（平台定位） | 三件套：凭据（OAuth 生命周期，现状）+ 公共档案（昵称/简介/头像，agent 可基于定位起草）+ 适配默认（语言/格式，选题分流用） | 用户连接 + agent 起草档案 |
| topics（选题库） | §5 | agent 提议 + 用户随手记 |
| assets（素材档案） | back-catalog 挖矿底座（"我 2024 年说过 X 什么"）；项目引用根级素材 | 上传（现状链路） |

## 4. 选题库（运营中枢）

**选题是一等公民，带完整生命周期**：

```
灵感（agent 提议 / 用户随手记）→ 已排期 → 生产中 → 已发布 → 有数据
   ↑                                                          │
   └────────── 数据回流（P2）校准选题排序 + 定位微调建议 ◄──────┘
```

- **选题卡 = 发射单元**：点一张卡，任务书已预填（关联素材 + 目标渠道 + 按渠道适配默认带出的语言/格式），进 chat 确认即跑——复用 chat 唯一意图面，无第二入口。
- **与配方卡的分工**：配方卡回答"新用户能做什么"（通用模板）；选题卡回答"老用户下一条做什么"（你的下一步）。两者共用同一发射机构。
- **来源优先级**：素材档案挖矿为主（用户的差异化就是真实素材，反 slop 战略）；"你 2024 年那场关于 X 的演讲还没做成过任何东西"是选题的标准形态。对标分析（小红书链路的"对标笔记/账号"格）**不作支柱**——与反 slop 定位相悖，P2 降级为选题校准信号。
- **排序信号 v1**（无回流时）：新鲜度 + 用户选用行为 + 素材覆盖度；发布数据回流（P2）到位后接入表现信号。

## 5. 产品流程（重写后）

**首次来访**：chat 诊断（听众/目的，一轮封顶）→ agent 起草定位 + 身份卡 → 确认 → 自动从素材挖人设 → agent 端出第一批选题（素材挖矿）→ 用户挑一张 → 首跑。每一步都回答"现在该做什么、为什么、下一步是什么"。

**回访**：home = 定位面板（选题管道 + 最近产物 + 渠道状态），composer 保留但主 CTA 是选题卡。**用户到来即彷徨从此每次访问都有答案，不只是第一次。**

**生产流**：选题 → 预填任务书 → run → 产物 → 精修（chat/editor）→ 发布到渠道 →（P2）数据回流 → 选题排序与定位微调。

**project 退居内部执行容器**：用户心智里没有"项目"，只有"我做过的内容"和"我该做的下一条"。用户可见工作单元 = 选题（管道）+ 产物（成果库）；projects/runs 留管线层做分组与重跑载体。

## 6. 命名

| 词 | 裁决 |
|---|---|
| `positioning` / 定位 | 根概念，三层同词族（表 `positionings` / 导航「定位」/ agent 台词"找定位"）。en 复数 "positionings" 略生硬，但多实例管理是边缘 UI，可接受 |
| `persona` / 人设 | **收窄回表达本义**（风格/声纹/皮肤），作为定位的逻辑分区名存活（人设页分区 tab / prompt 上下文 / 词汇表）；风格六件保持平铺列，不做物理 JSONB 嵌套 |
| `topics` / 选题 | 新一等公民；用户侧 zh「选题」/ en 待定（topics / ideas） |
| `brand` | **维持皮肤块一词不动**（ADR-038 全栈一词先例）；不引入 `look` |
| 品牌 / personal brand | **营销承诺层词**：落地页叙事照用，不进产品内概念与导航 |
| `project` | 退内部执行容器；用户可见层让位选题 + 产物 |

声纹资产挂**用户层**：声带是人的不是定位的，多定位引用同一份克隆，不重复录制不重复花配额。

## 7. 实施切分（四刀，排期见 PROGRESS §2 第六~八周）

1. **概念刀**：`personas`→`positionings` 全栈改名（speakers→personas 先例同构，纯机械）+ 内容定位字段入表 + 定位页三分区 + `channel_accounts.positioning_id` + composer 身份控件随根改名；
2. **定位对话化**：chat 诊断产出定位草案 + 确认环节（intent router 扩展；诊断纪律随 ADR-052 判词 5 改写——每轮一问、每问可一词答）；
3. **选题库**：`topics` 表 + 生命周期 + 选题 agent（roster 新声明，定位 × 素材挖矿）+ 选题卡 + 发射链；
4. **回访 home + 素材上提**：定位面板 v1 + assets 归根。

每刀施工前另立简报（`docs/tasks/`），本文只管概念架构。

## 8. 明确不做

- **对标作为支柱**：与"真实素材反 slop"定位相悖；P2 仅作选题校准信号。
- **工具格形态**：运营链各环节（梳理定位/起草档案/提议选题）全走 chat 意图面 + agent 顾问姿态，不出现"AI 取名 / AI 拆解"按钮墙。
- **昵称取名场景**：目标用户是有名字有机构的专家，不是痛点；渠道公共档案的起草优化才是。

## 9. 开放问题

- **home v1 形态**：定位面板是全量重做还是 composer + 选题区的过渡形态，随第三/四刀施工简报定。
- **en 侧选题词**：topics / ideas 待 UI 文案定稿时裁决。
- **定位与项目的过渡关系**：存量 projects 无 positioning 挂载的读容忍策略，第一刀简报定。
